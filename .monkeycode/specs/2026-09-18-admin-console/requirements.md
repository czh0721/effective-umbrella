# 管理后台扩展（Admin Console Expansion）需求文档

- Feature: `admin-console`
- 日期: 2026-09-18
- 状态: 待评审（用户已确认模块范围、UI 风格、权限模型）
- 关联: 扩展 `2026-09-14-credit-billing`、`2026-09-17-credit-expiry-distill`、`2026-09-18-package-tiers-bonus`

## 背景

当前后台只有概览、举报、用户、积分配置、审计、系统六个分区，运营所需的数据洞察、用户治理、
内容审核、订单计费、公告投放、运维处置等能力缺失。用户反馈「功能太少」，并要求界面排版与
UI 重新设计，与用户端统一为念念玻璃风（浅色）。

## 关键决策（用户确认）

1. **模块范围**：本期覆盖七大类——数据看板、用户管理增强、内容与人设、计费与订单、
   运营投放、系统与运维、管理员与权限。
2. **UI 风格**：延续念念玻璃风（浅色），复用用户端设计令牌（雾玻璃、紫色、圆角、氛围光）。
3. **权限模型**：单一超级管理员，不引入角色分级；所有管理员拥有同等权限。

## 术语

- **看板（Dashboard）**：以指标卡与趋势图呈现平台运营数据的页面分区。
- **订单（Order）**：用户使用念念币购买积分套餐产生的一条购买记录。
- **公告（Announcement）**：管理员发布、在用户端展示的站内通知。
- **功能开关（Feature Flag）**：控制某项产品功能是否对用户端开放的配置项。
- **处置（Resolve）**：管理员对举报或内容做出的处理动作。
- **审计（Audit）**：管理员写操作留下的不可变操作记录。

## 需求（EARS）

### A. 数据看板

- R1: The system shall 在概览分区展示总用户数、今日活跃用户数、总人格数、今日对话轮次、
  今日消耗积分、今日新增用户、待处理举报数七项核心指标。
- R2: WHEN 管理员选择 7 天、30 天、90 天中任一范围, the system shall 返回按自然日聚合的
  新增用户、活跃用户、对话轮次、营收四项趋势数据。
- R3: The system shall 展示注册到创建人格、创建人格到绑定微信、绑定微信到购买套餐三个
  环节的转化率。
- R4: WHEN 某日某项指标数据缺失, the system shall 以 0 补齐该日数据点并保持日期轴连续。
- R5: The system shall 在获取看板数据时对超过一日的聚合结果使用不高于 60 秒的缓存。

### B. 用户管理增强

- R6: The system shall 在用户列表提供按用户名关键字搜索、按账号状态筛选、按注册时间范围
  筛选、按积分余额区间筛选四种过滤方式。
- R7: The system shall 对用户列表按 20 条每页分页，并返回总条数。
- R8: WHEN 管理员打开某个用户详情, the system shall 展示该用户资料、人格列表、微信绑定状态、
  积分余额、念念币余额、蒸馏券余额、最近 20 条积分流水与最近 20 条念念币流水。
- R9: The system shall 支持管理员为用户添加备注与标签，并在用户列表与详情中展示。
- R10: WHEN 管理员停用某用户并填写理由, the system shall 记录该理由、停用时间与操作管理员，
  并立即使该用户全部会话失效。
- R11: WHEN 管理员启用某用户, the system shall 清除停用理由与停用时间并保留历史审计记录。
- R12: WHEN 管理员重置某用户密码, the system shall 立即使该用户全部会话失效。
- R13: WHEN 管理员调整某用户积分或念念币, the system shall 在同一事务内更新余额并写入对应流水，
  流水记录操作管理员与调整原因。
- R14: The system shall 支持把当前筛选结果导出为 CSV，导出列包含用户编号、用户名、昵称、
  状态、积分余额、念念币余额、人格数、注册时间。

### C. 内容与人设

- R15: The system shall 提供人格列表，支持按用户名或人格名搜索，并展示人格状态、所有者、
  创建时间与最近活跃时间。
- R16: WHEN 管理员打开某个人格详情, the system shall 展示人格卡基本字段、记忆条数、联系人数量、
  对话轮次与最近 20 条记忆摘要。
- R17: WHEN 管理员停用某个人格, the system shall 停止该人格的自动回复并在详情中标记停用状态。
- R18: The system shall 提供朋友圈内容列表，支持按用户名、人格或时间范围筛选。
- R19: WHEN 管理员删除某条朋友圈内容, the system shall 记录删除操作与操作管理员到审计。
- R20: WHEN 管理员查看某条举报, the system shall 展示该举报关联的用户、人格与内容摘要。

### D. 计费与订单

- R21: The system shall 在套餐管理按月度、季度、年度分组展示套餐，并支持新增、编辑、启停与排序。
- R22: The system shall 在每次套餐购买成功时写入一条订单，包含用户、套餐名称、基础积分、
  赠送积分、赠送蒸馏券、消耗念念币、购买时间与幂等键。
- R23: The system shall 提供订单列表，支持按用户名、套餐、时间范围筛选，并按时间倒序返回。
- R24: The system shall 支持把订单列表导出为 CSV。
- R25: The system shall 展示按 7 天、30 天、90 天范围聚合的营收汇总，营收以消耗念念币计量，
  并同时展示发放积分总量。
- R26: The system shall 支持批量生成兑换码、按批次与状态筛选兑换码、导出兑换码为 CSV。
- R27: WHEN 管理员作废某个未使用的兑换码, the system shall 把该兑换码状态置为作废并记录审计。
- R28: The system shall 提供积分批次列表，支持按用户名与到期时间范围筛选，并展示剩余积分。

### E. 运营投放

- R29: The system shall 支持创建公告，包含标题、正文、生效时间、结束时间与启用状态。
- R30: WHEN 当前时间位于公告生效区间且公告处于启用状态, the system shall 在用户端展示该公告。
- R31: The system shall 支持向全体用户或指定用户发送站内通知，站内通知写入用户通知中心。
- R32: WHEN 管理员向指定用户发放积分或蒸馏券, the system shall 复用现有发放接口并写入流水与审计。
- R33: The system shall 在平台配置中提供新用户注册赠送积分与默认积分有效期的维护入口。

### F. 系统与运维

- R34: The system shall 在系统分区展示服务运行时长、数据库可写状态、消息出站队列统计与
  最近失败记录。
- R35: The system shall 提供微信绑定列表，展示用户、绑定阶段与运行状态。
- R36: WHEN 管理员对某个绑定执行强制下线, the system shall 停止该绑定对应的微信运行实例。
- R37: The system shall 提供任务列表，支持按状态筛选，并展示任务类型、进度与最近错误。
- R38: WHEN 管理员重试某个失败任务, the system shall 把该任务重新入队并记录审计。
- R39: The system shall 提供功能开关列表，包含朋友圈自动发布、微信登录与平台模型三项开关。
- R40: WHEN 管理员切换某个功能开关, the system shall 持久化开关状态并在用户端接口中即时生效。
- R41: The system shall 支持触发一次数据库备份，并展示最近备份文件列表与时间。

### G. 管理员与审计

- R42: The system shall 提供管理员列表，展示用户名、名称、状态、是否启用双因素与最近登录时间。
- R43: The system shall 支持创建管理员、启用或停用管理员、重置管理员密码、重置管理员双因素。
- R44: WHEN 管理员停用某个管理员账号, the system shall 立即使该管理员全部会话失效。
- R45: The system shall 提供审计日志列表，支持按操作者、操作类型、目标与时间范围筛选。
- R46: The system shall 支持把审计日志按当前筛选导出为 CSV。
- R47: The system shall 对所有 `/api/admin/` 写操作记录审计，包含操作管理员、操作类型、目标与时间。

### H. 举报与告警

- R48: The system shall 提供举报列表，支持按状态与时间范围筛选，并展示举报类别、举报人与关联人格。
- R49: The system shall 支持管理员把举报处置为已解决或已忽略，并记录处置管理员与时间。
- R50: The system shall 提供管理员告警列表与未读计数，并支持一键标记全部已读。

### 非功能需求

- R51: The system shall 要求全部 `/api/admin/` 接口携带有效管理员会话，缺失会话时返回 401。
- R52: The system shall 对管理员写操作启用 CSRF 校验，并对管理员登录启用速率限制。
- R53: WHEN 任一管理端接口处理出现未预期异常, the system shall 返回可读错误信息并记录服务端日志。
- R54: The system shall 在宽 1024 像素以上视口展示固定左侧导航，在较窄视口以抽屉方式展示导航。
- R55: The system shall 复用用户端设计令牌，保持浅色玻璃风，并移除深色主题。
- R56: The system shall 保持现有后台接口路径与响应字段的向后兼容，既有调用方无需改动即可继续使用。
