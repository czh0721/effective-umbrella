# 账号安全强化（Account Security Hardening）需求文档

- Feature: `account-security-hardening`
- 日期: 2026-09-18
- 状态: 已评审（用户确认全部关键决策）
- 关联: 扩展 `2026-09-13-multi-user-personas`、`2026-09-18-admin-console`

## 背景

平台已有用户名密码注册登录、scrypt 加盐哈希、按来源 IP 与用户名的滑动窗口限流、用户与管理员各自的双因素（TOTP）能力，以及登录后自助改密与「退出所有设备」。当前缺口集中在三点：

1. 密码只校验长度下限（8 位），弱密码与超长密码都可通过。
2. 登录失败只有短时全局限流（10 次 / 5 分钟），既无账户级锁定，也无失败提醒与后台可见的锁定状态，管理员无法主动解锁。
3. 管理员的 TOTP 是可选能力，未启用也能直接进入后台，缺少「必须启用」的强制策略。

本次在既有能力上补齐策略、锁定与强制双因素，不改变短信/邮件等外部依赖。

## 术语

- **弱密码**：长度不足、仅由单一字符类别构成，或命中内置常见弱密码字典的字符串。
- **账户锁定（Account Lock）**：某用户名在连续多次登录失败后，被系统在锁定窗口内拒绝登录的状态。
- **强制双因素（Enforced TOTP）**：要求管理员必须先完成 TOTP 绑定并通过校验才可调用后台接口的策略。
- **敏感操作**：改密、重置他人密码、启停管理员、解锁账户、调整积分与念念币。

## 需求（EARS）

### 密码强度策略

- R1: The system shall 在注册、自助改密、管理员重置密码与管理员创建密码四条路径上统一执行密码强度校验。
- R2: IF 密码长度少于 10 个字符或超过 128 个字符, then the system shall 拒绝并返回可读错误。
- R3: IF 密码未同时包含大写字母、小写字母、数字与符号四类字符, then the system shall 拒绝并提示缺少的字符类别。
- R4: IF 密码命中内置常见弱密码字典或与用户名高度相似, then the system shall 拒绝并返回可读错误。
- R5: WHILE 密码强度校验失败, the system shall 保持原密码不变。

### 登录失败锁定

- R6: WHEN 同一用户名在 15 分钟内连续 5 次密码校验失败, the system shall 锁定该账户 15 分钟并拒绝后续登录尝试。
- R7: IF 账户未处于锁定状态且密码校验失败, then the system shall 返回统一的「用户名或密码错误」响应，避免暴露账户是否存在。
- R8: WHEN 账户被锁定, the system shall 写入一条账户锁定记录并生成一条面向管理员的安全提醒。
- R9: WHEN 账户锁定窗口结束后登录成功, the system shall 清除该账户的失败计数与锁定状态。
- R10: WHEN 用户对已锁定账户发起登录, the system shall 返回 429 并在响应中给出锁定剩余分钟数与 `Retry-After` 头。
- R11: The system shall 保留按来源 IP 的滑动窗口限流，作为账户锁定的补充。

### 管理员强制双因素

- R12: The system shall 在平台层提供「管理员强制双因素」开关，默认关闭。
- R13: WHILE 强制双因素开关开启且某管理员尚未启用 TOTP, the system shall 拒绝该管理员对后台数据接口的访问，仅允许其访问双因素绑定相关接口。
- R14: WHEN 管理员首次通过密码登录且尚未绑定 TOTP, the system shall 引导其进入绑定流程并在绑定成功后允许访问后台。
- R15: WHILE 强制双因素开关开启, the system shall 在每次管理员登录时校验 TOTP 验证码。
- R16: The system shall 在后台管理员列表展示每个管理员的双因素启用状态。
- R17: WHEN 超级管理员重置某管理员的双因素, the system shall 记录审计并在该管理员下次登录时重新要求绑定。

### 解锁与审计

- R18: The system shall 在后台提供账户解锁操作，超级管理员可对已锁定账户解锁。
- R19: WHEN 超级管理员解锁账户, the system shall 清除该账户的失败计数与锁定状态，并写入审计。
- R20: WHEN 发生解锁、强制双因素开关变更、管理员双因素重置, the system shall 向管理员写入安全提醒。

### 自助改密与会话

- R21: WHEN 用户自助改密成功, the system shall 使该用户除当前会话外的其他会话立即失效，并保留当前会话。
- R22: WHEN 用户自助改密成功, the system shall 校验新密码不等于当前密码，并返回可读错误。
- R23: The system shall 在账号安全中心展示密码强度要求与最近一次改密时间。

## 关键决策（用户确认）

1. **密码强度档位**：采用高强度四类齐全——长度 10–128，且必须同时包含大写字母、小写字母、数字与符号，并拦截常见弱密码与与用户名高度相似的密码。
2. **锁定策略**：采用账户级「15 分钟内连续 5 次失败 → 锁定 15 分钟」，超级管理员可解锁；保留按来源 IP 的滑动窗口限流作为补充。
3. **强制双因素范围**：仅对管理员强制，普通用户的双因素保持可选；由平台开关控制，默认关闭。
