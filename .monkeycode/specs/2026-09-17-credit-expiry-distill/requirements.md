# 积分套餐有效期与蒸馏单独购买（Credit Expiry & Distill Purchase）需求文档

- Feature: `credit-expiry-distill`
- 日期: 2026-09-17
- 状态: 已评审（用户确认全部关键决策）

## 背景

现有计费体系里，积分是 `users.credits` 上的一个整数余额，一次发放永久有效；积分套餐
（体验包 / 标准包 / 尊享包）只有积分数量与念念币价格，没有时间维度；蒸馏目前免费。

用户要求：积分套餐带时间限制（月度 / 季度 / 年度），到期没用完的积分清零；蒸馏（创建
分身与重蒸馏）需要单独购买。

这要求积分从「单一永久余额」升级为「按批次记账、可按批次到期清零」，并新增可单独购买
的蒸馏券。

## 关键决策（用户确认）

1. **到期范围**：所有积分统一有效期，不存在永久积分；注册赠送、管理员发放、套餐购买
   产生的积分都按批次到期清零。
2. **时长口径**：固定天数，月度 30 天、季度 90 天、年度 365 天，自发放时刻起算。
3. **赠送与发放**：管理员发放积分时可选择 30 / 90 / 365 天；注册赠送使用后台配置的
   默认天数。
4. **历史存量**：升级时清空升级前已存在的积分余额（如当前 4720），并写入一条说明流水。
5. **蒸馏券**：蒸馏成功时扣 1 张；新建蒸馏与重蒸馏都计；从预设 / 市场创建不扣券；
   失败不扣券。不向新用户赠送，单张价格默认 60 念念币，价格与「是否赠送 / 赠送数量」
   由后台配置。
6. **余额口径不变**：聊天仍按轮扣积分，每轮单价沿用现有配置。

## 术语

- **积分（Credit）**：聊天回复的计价单位，按轮扣减。
- **套餐（Package）**：后台维护的积分档位，含名称、积分数量、念念币价格、有效期天数、
  排序与启用状态。
- **有效期天数（Validity Days）**：套餐积分自购买起可用的固定天数，取值 30 / 90 / 365。
- **积分批次（Credit Batch）**：一次积分发放形成的独立额度，含来源、总量、剩余量、生效
  时间与到期时间。
- **到期清零（Expire）**：批次到期后，其未消耗的剩余积分归零且不再可用。
- **蒸馏券（Distill Ticket）**：用于发起一次蒸馏的凭证，独立于积分，以念念币购买。
- **重蒸馏（Redistill）**：对已存在的人格重新蒸馏。
- **平台模型（Platform Model）**：管理员统一配置、供全体用户使用的大模型服务。

## 需求（EARS）

### 套餐有效期配置

- R1: The system shall 在套餐配置中提供有效期天数字段，取值包含 30、90 与 365。
- R2: When 管理员创建或更新套餐, the system shall 保存该套餐的有效期天数，并在用户端
  按天数展示可用的时长。
- R3: If 套餐的有效期天数取值不在 30 / 90 / 365 之内, then the system shall 拒绝保存并
  返回可读错误。
- R4: The system shall 在套餐列表同时展示积分数量、念念币价格与有效期天数。

### 积分批次与到期清零

- R5: When 用户购买套餐成功, the system shall 创建一条到期时间等于购买时刻加套餐有效期
  天数的积分批次，并记录套餐名称。
- R6: When 管理员发放积分成功, the system shall 按管理员选择的天数创建积分批次。
- R7: When 新用户注册成功, the system shall 按后台配置的默认天数创建注册赠送积分批次。
- R8: Where 批次到期时间已到达, the system shall 将该批次的剩余积分清零，并写入一条积分
  流水说明清零批次与积分数。
- R9: If 批次到期时剩余积分为 0, then the system shall 跳过流水写入且不影响其他批次。
- R10: While 批次尚未到期, the system shall 将该批次剩余积分计入用户可用余额。
- R11: The system shall 在扣除积分消耗时优先使用到期时间最早的批次额度。
- R12: The system shall 保证用户可用余额等于全部未到期批次剩余积分之和。
- R13: The system shall 在服务运行期间持续巡检到期批次，巡检间隔不超过 1 小时。

### 到期提醒

- R14: When 某批次距离到期不足 72 小时且该批次尚未提醒过, the system shall 向该用户发送
  一条站内提醒，说明即将清零的积分数量与到期时间。
- R15: The system shall 对同一批次最多发送一条到期提醒。

### 蒸馏券购买与消耗

- R16: The system shall 提供蒸馏券商品配置，包含是否向新用户赠送、赠送数量与单张念念币
  价格。
- R17: When 用户购买蒸馏券成功, the system shall 增加该用户蒸馏券数量并写入一条蒸馏券
  流水。
- R18: If 用户念念币余额小于蒸馏券单价, then the system shall 拒绝购买并返回可读提示，
  且不做任何扣减。
- R19: When 用户发起蒸馏且蒸馏券数量大于 0, the system shall 预扣 1 张蒸馏券后开始蒸馏。
- R20: If 用户蒸馏券数量为 0, then the system shall 拒绝发起蒸馏，返回「需要先购买蒸馏券」
  的可读提示，且不做任何扣减。
- R21: When 蒸馏成功完成, the system shall 保留预扣的 1 张蒸馏券并写入消耗流水。
- R22: If 蒸馏失败或被取消, then the system shall 退还预扣的 1 张蒸馏券并写入退还流水。
- R23: While 用户从预设或市场创建分身, the system shall 不扣减蒸馏券。
- R24: The system shall 在用户端展示蒸馏券剩余数量与购买入口。

### 用户端展示

- R25: The system shall 在积分卡与套餐页展示当前可用积分、最近到期时间与即将清零的积分数。
- R26: When 用户查看某套餐, the system shall 展示该套餐的有效期天数与到期清零规则。
- R27: The system shall 在积分明细中区分「套餐到账」「赠送」「管理员发放」与「到期清零」。

### 兼容与历史数据

- R28: When 升级到批次记账机制, the system shall 将升级前已存在的积分余额清零并写入一条
  说明流水，且该清零操作在升级后仅执行一次。
- R29: The system shall 保证升级清零操作幂等，重复启动不会重复清零。
