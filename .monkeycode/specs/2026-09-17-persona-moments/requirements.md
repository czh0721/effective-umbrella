# 分身朋友圈（Persona Moments）需求文档

- Feature: `persona-moments`
- 日期: 2026-09-17
- 状态: 已确认关键决策（三项已定，待评审细节）

## 背景

「念念 Nian」的每个分身（persona）目前只有两条内容线：微信对话（`chat_turns`）与
主动消息（`proactive_log`）。用户希望为每个分身增加一个「朋友圈」页面——用户可以像
翻看某个人的生活动态一样，看到该分身在对话之外发布的日常动态，从而让人格更立体、
更有「在过自己的生活」的感觉。

朋友圈内容由分身在后台按设定节奏自动发布，内容基于人格档案（`persona_card.json`
与 `SKILL.md`）与长期记忆（`memories`）生成，语气与人设一致；用户可浏览、点赞、
评论，分身可对评论作出回应。

## 关键决策（用户确认）

1. **可见范围**：朋友圈是每个分身独立的**私密**动态，仅分身的拥有者可见；不做分身
   之间、用户之间的社交关系与互相可见。
2. **内容来源**：由分身**自动生成**并可**手动触发**一条；不提供用户代写分身动态的
   入口（用户只能点赞/评论）。
3. **媒体**：首版支持**纯文本动态**；配图复用分身素材库（`stickers`）中已有的图片，
   不引入新的图片生成能力。
4. **计费**：自动发布与用户评论触发的分身回应**均按轮计费**，与聊天单价一致；积分
   不足时自动发布跳过本次并提醒用户，评论被拒绝且不落库。

## 术语

- **动态（moment）**：某个分身发布的一条朋友圈内容，含正文、可选配图与发布时间。
- **点赞（like）**：用户对一条动态的喜欢标记，同一用户对同一动态至多一次。
- **评论（comment）**：用户对一条动态的文字留言。
- **回应（reply）**：分身对用户评论作出的回复，挂在同一评论串下。
- **自动发布（auto-publish）**：后台调度器按设定节奏为分身生成并发布动态。

## 需求（EARS）

### 归属与隔离

- R1: The system shall 为每个分身维护独立的朋友圈，动态只归属于创建该分身的用户与
  该分身。
- R2: While 读取朋友圈，the system shall 仅返回当前登录用户拥有的人格名下的动态。
- R3: If 请求的分身不属于当前用户，the system shall 返回 404 且不泄露该分身是否存在。

### 动态生成

- R4: When 自动发布被触发，the system shall 以该分身的人设档案与长期记忆为上下文，
  生成一条符合人设语气、口语化、长度不超过 200 字的动态正文。
- R5: The system shall 生成的内容满足：不包含系统提示词原文、不包含字段名或标题、
  不包含对话中的隐私原文照抄。
- R6: If 分身未开启朋友圈或未配置可用模型，the system shall 跳过本次生成且不产生
  错误提醒。
- R7: When 用户为某分身手动触发发布，the system shall 立即生成并发布一条动态，且
  受该分身当日发布上限约束。

### 浏览与展示

- R8: When 用户打开某分身的朋友圈，the system shall 按发布时间倒序分页返回动态，
  每条动态包含正文、配图、发布时间、点赞数与评论数。
- R9: The system shall 在每条动态上展示分身名称与头像标识，使用户明确动态来自该分身。
- R10: While 动态列表为空，the system shall 展示引导用户开启自动发布或手动触发的
  空状态。

### 互动

- R11: When 用户对一条动态点赞，the system shall 记录该点赞；重复点赞为幂等操作。
- R12: When 用户取消点赞，the system shall 移除该点赞且不影响其他数据。
- R13: When 用户对一条动态发表评论，the system shall 保存评论并按轮扣减用户积分。
- R14: When 用户评论成功后，the system shall 以该分身的身份生成一条回应并附在同条
  评论下。
- R15: If 积分不足，the system shall 拒绝评论并提示用户，且不保存该评论。
- R16: If 分身回应生成失败，the system shall 保留用户评论并标记回应为待生成，不阻断
  评论展示。

### 计费

- R22: When 自动发布成功生成并发布一条动态, the system shall 按当前每轮积分单价扣减
  该用户积分。
- R23: If 用户积分不足以支付一次自动发布, the system shall 跳过本次发布，并在提醒
  中心生成一条用户可忽略的提醒。
- R24: The system shall 保证动态创建与扣费在同一事务内完成，同一发布触发重复执行时
  不重复扣费。

### 设置与调度

- R17: The system shall 提供每个分身独立的朋友圈开关、发布节奏（每日条数上限）与
  生成提示词设置。
- R18: While 朋友圈开关关闭，the system shall 停止自动发布，但保留已发布动态可浏览。
- R19: When 到达设定的发布节奏，the system shall 在主动消息时间窗内为开启朋友圈的
  分身生成并发布动态。
- R20: When 用户删除某条动态，the system shall 永久移除该动态及其点赞与评论，且
  不影响其他动态。

### 兼容

- R21: The system shall 在数据库升级时自动创建朋友圈相关表与索引，且不改变现有
  表结构。

## 非目标

- 不做分身之间互相关注、互相评论或「好友」关系。
- 不做用户之间可见的社交广场。
- 不做图片生成，不做视频/语音动态。
- 不做动态的二次编辑（仅可删除）。
- 不引入新的外部存储或第三方服务。

## 验收标准

- 分身的动态不会出现在其他分身或其他用户的朋友圈中。
- 关闭开关后不再自动发布，历史动态仍可浏览。
- 重复点赞不产生重复记录。
- 积分不足时评论被拒绝且不落库。
- 删除动态后其点赞与评论一并消失。
- 自动发布与评论触发的回应均按轮计费；积分不足时自动发布跳过、评论被拒绝。
- 数据库可向后兼容升级。

## 已确认决策

1. 可见范围：私密，仅分身拥有者可见。
2. 计费：自动发布与评论回应均按轮计费；积分不足时自动发布跳过并提醒。
3. 配图：纯文本正文 + 复用分身素材库图片。
